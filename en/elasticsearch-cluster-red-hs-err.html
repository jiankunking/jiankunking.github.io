Notes on an Elasticsearch cluster incident:
the analysis, the troubleshooting, and the recovery.

🕰️ Version note: This post was written in 2025, against an Elasticsearch 7.16.2 cluster. The technology moves fast — read it alongside the version you actually run.

Background

In the morning a colleague opened a group chat to report write timeouts on an ES cluster they use. Checking the cluster health showed it was already red.

  • This was a 3 × 8-core, 32 GB cluster (JVM heap configured at 16 GB)
  • At the time of the failure the cluster held 5000 indices, each with 6 shards and 1 replica — that is, 12 shards per index
    • The shard count had already reached 6w (60,000), not counting Elasticsearch's own system indices
  • The cluster instances had been restarted
  • Data volume was roughly 480 GB

Does any of this feel familiar?
